# NewLife.Cube.WeCard 架构设计

## 1. 定位

与 `NewLife.Cube.QyWeixin` / `NewLife.Cube.Approval` 同类：**魔方功能扩展包**。宿主引用 NuGet，在 `AddCube`/`UseCube` 旁调用注册扩展，即可获得微卡 HTTP 客户端与回调端点。不修改魔方框架源码。

## 2. 包形态（已确认方案 A）

同一源码双包，`CubeHost` 切换：

- `NewLife.Cube.WeCard` → 依赖 `NewLife.Cube.Core`（MVC）
- `NewLife.Cube.WeCard.WebApi` → 依赖 `NewLife.Cube`（WebApi）

程序集名相同，公开 API 相同。魔方依赖 `6.15.2026.901`，目标 `net8.0`。

## 3. 逻辑分层

```
宿主 (Cube WebApi / MVC)
  └── NewLife.Cube.WeCard[.WebApi]
        ├── WeCardOptions / WeCardCredential   # AppKey、AppSecret、ocode、BaseUrl、回调 Token/AES
        ├── WeCardClient                       # access_token 缓存 + REST 调用 open.wecard.qq.com
        ├── WeCardCrypt / WeCardSign           # AES/CBC、签名校验
        ├── WeCardOAuth                        # H5/PC/MNP 授权 URL 与换票
        ├── Controllers/WeCardCallbackController
        ├── Events/IWeCardEventHandler         # 成员/组织等事件分发
        └── (可选) Jobs：定时拉取组织成员 → 映射魔方 User/Department（只拉不推，对齐企微作业策略）
```

## 4. 关键约定

- 公有云 BaseUrl：`https://open.wecard.qq.com`（路径以官方文档为准，如 `/cgi-bin/oauth2/token`）
- 私有化：`{PrivateGateway}/kong` + 相同 path
- Token：内存/缓存按 `expires_in` 提前刷新；按 ocode 分桶
- 请求：`application/json`；统一解析 `errcode`/`errmsg` 或文档约定字段，抛可诊断异常
- 回调：验签 → 解密 `raw_data` → 分发；响应 `{"code":0,"message":"ok"}`（以事件文档为准）

## 5. 与魔方集成

- **用户映射**：电子卡号/`card_number` ↔ 魔方 `User` 扩展字段或映射表（首版可只提供 Client，映射作业为可选）
- **权限**：管理端配置页走魔方菜单+权限；微卡管理员 OAuth 仅用于「嵌入微卡后台时的身份校验」可选中间件
- **审计**：出站调用与入站事件写魔方日志（ILog），不新建审计子系统

## 8. 风险

- 官方文档分 self / selfbuilt / third，路径与字段偶有不一致 → 以 selfbuilt 页面 + 联调响应为准  
- 「实现所有接口」体量大 → 必须分批；首版门禁定为 P0+P1 全绿，P2/P3 可随后迭代  
- 支付与门禁含金融/安防语义 → 默认薄封装、无默认开通，文档标明风险与所需权限申请
